# 报价、配送与执行

先确认产品适合需求，再比较匹配报价。用普通表格保留取得的字段，不要求简单追问也填完整记录。

## 产品身份与报价身份

| 记录 | 内容 |
|---|---|
| `product_identity` | 品牌、完整型号/P/N、代际、地区版本、配方、单包装容量/尺寸/内件数及固有配置；正装/补充装、是否带喷头、厂家标准套装等实际产品区别 |
| `offer` | 对应产品、平台/市场、卖家与履约者、成色、数量、交易套装及配件、币种、账号优惠、地址范围、核价时间与售后 |

同型号主机带不同幕、支架或配件，可对应同一主机，但不是同一购物篮。二手的成色、使用记录、凭证和退换不被全新同型号替代；电器另核电压、频率及地区保修。游戏本CPU/GPU/内存/硬盘不同，不按系列起售价比较同配。

识货、慢慢买、什么值得买、搜索及商品/联盟API可发现渠道和历史线索。回零售商核所选规格、数量及账号优惠；接口价不自动成为账号实付，更不能替代小红书原帖评论。未命中不证明全网无货、历史未更低或平台不卖。

## 算本次需要数量的价格

商品页、购物车、确认页和已付款结果分别记，不能跨阶段填数：

`本单应付 = 本次商品金额 − 确实可用现金优惠 + 运费 + 税费 + 必需服务费`

返现、积分和赠品估值不直接扣应付；会员、安装、上楼、跨境退运等相关成本另列。多件单价与本次总额分开，不为低单价擅自增购、开会员或改配置。未知税运/服务费就写已知小计加未知项，不宣布最低到手。

| 情形 | 核验内容 |
|---|---|
| 京东及普通零售券 | 目标SKU、门槛按原价还是实付、件数、会员资格、期限和叠加；旗舰店名不等于自营，评价可能混款 |
| 淘宝等预售 | 实付定金、抵扣额、尾款、分阶段优惠、尾款时段、退定条件和发货起点。总付款为实付定金加尾款，再加未计费用；抵扣额不再算一次现金优惠 |
| 拼多多等拼单 | 独购价、拼单价、成团状态/期限及失败处理；老客不套新客券。补贴、拼单及优惠按当前账号该单核 |
| 国补/地区补贴 | 当前地区、用户资格、SKU、核销条件、期限和叠加。展示补贴价不等于已取得，不为套补擅改地址、身份或数量 |
| Amazon/Temu等跨境 | 实际站点及收货国家、版本、币种、税是否含/预收、运费、关税清关、银行卡换汇费、当地库存、售后区域和退运 |

跨币保留原币总额、换算时间及汇率依据；估算不等于实际扣款。德国/美国地址截图不能当上海可配送或含税到手价。进口税预收、实税及可能返还分开；插头转换头不证明电压频率兼容，海外保修不自动转当地保修。

## 配送与购买时机

统一收货地区、规格、数量及尽量接近的核验时间。库存、现货/预售、发货期限、运输预计、送达日期及安装预约分别读。“24小时发货”不是“明天到”，“送楼下”不是含上楼安装。家具另核包装尺寸、楼梯/电梯和预约，缺费项先留空。

按当前订单已保存地址核到货，不沿用旧默认地址。用户说已选好而界面仍旧地址时指出矛盾，不能猜多个地址中的一个。公开比较仅留必要地区。只有一个渠道有到货证据时，只报该渠道承诺，不宣布全平台最快。

现在买或等，结合最晚需要时间、当前应付、同款历史窗口、已公告活动、券/尾款期限和适用价保。活动预告不保证目标SKU降价，历史低点不保证重现。无历史数据就留未知；低价日用品也考虑等待与调研成本，避免无限找价。

## 执行已有授权

设备接入、加购、订单、支付、会员及对外消息是不同范围。沿用用户已明确的商品、数量、金额、商家、地址及阶段，不擅加每次统一确认。关键授权缺失或商品/金额/履约条件实质变化时，先准备可审查结果，再补对应信息。

1. 操作前读回产品、报价、选中SKU和数量。加购后核商品行；角标仅是线索，按钮未响应先看结果，不连点。
2. 单品确认页检查没有夹带原购物车商品、顺手买、付费保障或会员。核已保存地址、优惠、税运服务费、总额和到货。
3. 按实际后果判断按钮阶段：“立即购买”可能只开确认页，也可能进入直接支付流程。只执行到授权阶段，支付认证由用户按工具规则完成。
4. 加购/提交/付款结果不明时，先只读车、订单或支付记录，防止重复。结果页或订单状态证明成功，点击不证明成功。
5. 分别报告已加车、已创建订单、待付款、已支付与配送状态。只加车或不支付时停在该阶段，不把确认页应付叫已实付成交价。

截图只留本次结果，公开前移除账号、地址、订单号、卡号、支付资料、购物历史及会话参数。联系商家或发消息须有对应授权。
